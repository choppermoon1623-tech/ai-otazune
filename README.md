# AIおたずね箱

生徒が直接AIを使えない環境で、**生徒が書いた「おたずね」を先生がAIに代わりに聞き、
中身を確かめてから生徒に返す**ための、1ファイルのWebアプリ。

`index.html` ひとつだけ。GitHub Pages に置けばそのまま動く。

---

## 流れ

```
生徒（匿名）                    Firestore                   先生（Googleログイン）
   │ 受付コード6文字を入れる          │                              │
   │ 構造化フォームに書く             │                              │
   ├──────── おたずね ──────────────▶│───── リアルタイムで届く ──────▶│
   │                                │                              │ ① AIに渡す文を自動で組み立て
   │                                │                              │   📋 コピー ／ 🤖 AIに聞く
   │                                │                              │ ② 目を通して直す
   │◀────── 答えが自動で出る ────────│◀────── 生徒に返す ────────────┤
```

- 生徒の端末に**AIは一切入らない**。AIに触るのは先生の画面だけ。
- 先生は答えを**必ず一度読んでから**返す。そのまま素通しにならない作りにしてある。

## おたずねの型（構造化フォーム）

丸投げさせないために、型ごとに「なぜ知りたいか」「自分で調べたこと」「どこで行きづまったか」を書かせる。
ここがこのアプリのいちばん大事なところで、AIに渡す文もこの項目からそのまま組み立てる。

| 型 | 書かせること | 既定の答え方 |
|---|---|---|
| 🔎 調べて教えてほしい | 知りたいこと／なぜ／自分で調べたこと／行きづまり | 事実と確かめ方を重んじる |
| ✏️ 書いた文を見てほしい | 目的／読む人／自分が書いた文／直したいところ | ヒント中心（書き直して返さない） |
| 💡 考えの手がかりがほしい | テーマ／条件／自分の案／行きづまり | しっかり説明する |
| 💬 自由に書く | たのみたいこと | しっかり説明する |

答え方の方針は1件ごとに先生が切り替えられる。どの方針でも共通で、

- 中学生に分かる言葉で書く
- 確かでないことは「はっきりしない」と正直に書く
- 生徒が自分で確かめられる方法を必ず添える
- **そのまま提出できる完成品は書かない**

を指示している。AIに渡す文は「AIに渡す文を見る／手で直す」から全文を確認・編集できる。

## AIの呼び出し方（2通り・切替式）

| | コピー方式（既定） | 自動方式 |
|---|---|---|
| 準備 | 不要 | 設定にAnthropic APIキーを入れる |
| 費用 | 0円 | 従量課金 |
| 手順 | 📋 でコピー → Claude/ChatGPTに貼る → 答えを貼り戻す | 🤖 AIに聞く（回答が流れてくる） |

APIキーは**その端末のブラウザ（localStorage）にだけ**保存され、クラウドには一切出ない。
共用PCや生徒が触る端末には入れないこと。空にすれば消える。

自動方式は Anthropic Messages API を直接叩く（既定 `claude-opus-5`、ストリーミング、adaptive thinking）。
設定で Sonnet 5 / Haiku 4.5 にも切り替えられる。

## データの置き場所

**このアプリ専用の Firebase プロジェクト `ai-otazune`（東京リージョン asia-northeast1）** を使う。
電子教務手帳（`kyoumu-techou`）とは別プロジェクトで、成績データとは完全に切り離してある。

> 分けてある理由：無料枠はプロジェクト単位なので、同居させるとおたずね箱が枠を使い切った日に
> 教務手帳の同期まで止まる。ルールの書き間違いが成績データに及ぶ心配も無くなる。

```
otazune/{受付コード}                 { v, ownerUid, title, note, kinds, nameMode, open, createdAt, updatedAt }
otazune/{受付コード}/reqs/{自動ID}    { v, ownerUid, authorUid, no, name, kind, fields,
                                      status, answer, memo, policy, createdAt, updatedAt, answeredAt }
```

- `status` … `new`（未対応）→ `work`（対応中）→ `done`（返した） ／ `ng`（見送り）
- 受付コードは6文字。まぎらわしい **I O 0 1 を外した32文字**から選ぶ。
- **氏名はクラウドに入る**。出したくないときは受付の設定を「出席番号だけ」にする。
- 生徒は匿名ログイン。**他人のおたずねは読めない**（ルールで `authorUid` 一致を必須にしている）。
  ブラウザのデータを消すと匿名IDが変わり、自分の過去のおたずねが見えなくなる点に注意。

## 公開するまでにやること

### 1. Authentication を始めて、ログイン方法を2つ有効にする ★必須

[Firebase コンソール](https://console.firebase.google.com/project/ai-otazune/authentication) →
Authentication を開き、**まず「始める」を押す**。

> 新規プロジェクトでは Authentication 自体が未初期化で、この一手間が要る。
> 飛ばすと `auth/configuration-not-found` になり、アプリには
> 「Firebase の Authentication がまだ始まっていません」と出る。

そのうえで「ログイン方法」タブで次の2つを有効にする。

- **Google** … 先生用。有効にするときプロジェクトのサポートメールを選ぶ欄が出る
- **匿名** … 生徒用。これが無いと生徒側が「このアプリの準備がまだ終わっていません」で止まる

### 2. Firestore のルールを反映する ★必須

ルールはこのフォルダの `firestore.rules`。**ルールを変えたら毎回これが要る**（忘れると permission-denied）。
`.firebaserc` に `ai-otazune` を書いてあるので `--project` は不要。

```
cd C:\Users\USER\Desktop\ClaudeCode\ai-otazune
firebase deploy --only firestore:rules
```

### 2-b. Authentication の承認済みドメインに GitHub Pages を足す ★必須

新しいプロジェクトなので、既定では `localhost` と `ai-otazune.firebaseapp.com` しか許可されていない。
Authentication → 設定 → 承認済みドメイン に **`choppermoon1623-tech.github.io`** を追加する。
これが無いと、公開URLからのGoogleログインが `auth/unauthorized-domain` で失敗する。

### 3. GitHub Pages に置く（実施済み）

リポジトリ `choppermoon1623-tech/ai-otazune`。main に push でデプロイ。
公開先は https://choppermoon1623-tech.github.io/ai-otazune/ 。

## 授業での使い方

1. 先生が「＋ 受付をつくる」で受付を作る（例: 3年2組 社会 調べ学習）
2. 「📺 コードを大きく出す」を黒板に映す。アドレス・6文字のコード・QRが出る
3. 生徒はアドレスを開き、「生徒として使う」→ コードを入れる（QRなら自動で入る）
4. 届いたおたずねを先生が1件ずつ開き、AIに聞いて、**読んで直してから**返す
5. 授業が終わったら「■ 受付を閉じる」。閉じているあいだは新しく出せない

見送りにすると理由が生徒に見える。「テストの答えを教えて」のような依頼はここで止める。

### Classroom に貼って配る

「📺 コードを大きく出す」の中の **「📋 Classroom用の案内文をコピー」** で、
受付名・コード付きリンク・生徒への注意をまとめた文ができる。そのまま Classroom に貼れる。

```
【AIおたずね箱】3年2組 社会 調べ学習

↓ここを開いて、おたずねを書いてください
https://choppermoon1623-tech.github.io/ai-otazune/?r=ABC123

・自分で調べてもわからなかったことを書きます
・先生が確かめてから答えを返します
・答えは、出したのと同じ端末で見てください

（うまく開けないときは https://choppermoon1623-tech.github.io/ai-otazune/ を開いて、
　「生徒として使う」を選び、受付コード ABC123 を入れてください）
```

授業時間外にも出せるのが利点。ただし次の2点に注意する。

- **リンクを知っている人は誰でも出せる。** 受付コードが唯一の合言葉。
  Classroom の外に流れると他の生徒も投稿できるので、**使い終わったら受付を閉じる**。
- **端末を変えると自分の過去のおたずねが見えない。** 生徒は匿名ログインなので、
  学校の端末と自宅のスマホは別人あつかいになる。出すことはどちらでもできるが、
  答えは出したのと同じ端末に出る。案内文にもその一文を入れてある。

先生自身がこのリンクを踏むと、役割が「先生」で記憶されているため先生画面のままになる。
動作確認はシークレットウィンドウか別端末で。

## 検証

`scratchpad/smoke/test_otazune.js` — 生徒用と教師用の jsdom を**同時に立ち上げ、
共通の偽Firestoreでつないで実際にやりとりさせる**統合テスト（103項目）。
受付の作成から、生徒の送信、先生の対応、答えの到達、受付の開閉、見送り、
プロンプトの中身、API通信の形（ヘッダ・モデル・ストリーム・エラー文言）まで見ている。

```
npm install jsdom
node scratchpad/smoke/test_otazune.js
```

jsdom は ES module script を実行しないので、`window.fbq` は beforeParse で偽物を刺している。
偽Firestoreの側でも「閉じている受付には出せない」「他人の分は読めない」を再現し、
ルールと実装の食い違いに気づけるようにしてある。

## 気をつけること

- **答えを素通しで返さない。** 先生が読む前提の作り。AIは事実を間違える。
- **受付コードが合言葉。** 口頭・黒板・QRでだけ配る。ネットに貼らない。
- 学校のネットワークが `firestore.googleapis.com` を塞いでいると動かない。事前に1台で試す。
- 生徒が書いた内容は先生に読まれる、と生徒側の画面にも明記してある。
